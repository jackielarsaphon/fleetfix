# ระบบแจ้งซ่อมรถบริการ — เวอร์ชัน React.js

พอร์ตมาจากไฟล์ `ระบบแจ้งซ่อมรถบริการ (standalone).html` ให้อยู่ในรูปโปรเจกต์ React (Vite + React 18, JavaScript ล้วน ไม่ใช่ TypeScript)

แอปอ่าน/เขียนข้อมูลผ่าน **Go API** ในโฟลเดอร์ [../stores](../stores) ซึ่งต่อ Postgres ของ Supabase
(ดูการออกแบบฐานข้อมูลที่ [supabase/README.md](supabase/README.md))

```
เบราว์เซอร์ → fleetfix-react → HTTP → stores (Go) → Postgres (Supabase)
```

ไม่มีกุญแจฐานข้อมูลอยู่ในไฟล์ JS ที่ส่งให้เบราว์เซอร์อีกแล้ว
และการสร้างใบงานเป็น transaction เดียวจริง ๆ ที่ฝั่งเซิร์ฟเวอร์

## เริ่มใช้งาน

ต้องรัน **2 อย่างพร้อมกัน** — API กับหน้าเว็บ

```bash
# เทอร์มินัลที่ 1 — API
cd stores
./run.ps1                    # http://localhost:8080  (build แล้วรัน)

# เทอร์มินัลที่ 2 — หน้าเว็บ
cd fleetfix-react
npm install
npm run dev                  # http://localhost:5173
```

ตรวจชนิดข้อมูลของชั้นเชื่อมต่อด้วย `npm run typecheck`

ถ้า API ไม่ได้รัน แอปจะขึ้นหน้าจอบอกวิธีให้
API อยู่ที่อื่นก็ตั้ง `VITE_API_URL` ใน `.env.local` (ค่าเริ่มต้น `http://localhost:8080`)

ครั้งแรกต้อง apply migration ในฐานข้อมูลหนึ่งครั้ง — ดู [supabase/README.md](supabase/README.md#วิธี-apply)

ระบบ **ไม่มีการล็อกอิน** ตามที่ออกแบบไว้ — ใครเข้าถึงหน้าเว็บหรือ API ได้ก็แก้ข้อมูลได้
เหมาะกับใช้ในวงปิดเท่านั้น ถ้าจะเปิดให้คนนอกเข้าถึงควรเพิ่ม auth ที่ชั้น Go API

## สิ่งที่ทำได้

- ดูรายการงานซ่อม 3 แบบ: ตาราง (แบบ A), การ์ด (แบบ B), คิวตามสถานะ (แบบ C)
- กรองตามสถานะ และค้นหาจากเบอร์รถ / อาการ / เลข PR / รหัสอะไหล่ / ชื่อช่าง
- เปิดใบงานเพื่อดูรายละเอียด แก้เลข PR รายอะไหล่ และกดเลื่อนสถานะงาน
  (แจ้งใหม่ → รออะไหล่ → กำลังซ่อม → เสร็จแล้ว)
- **แก้ไขใบงาน** — ปุ่ม "แก้ไข" ในหน้ารายละเอียด แก้ได้ทั้งเบอร์รถ สถานะ เลขไมล์ วันที่
  อาการ อาการหลัก ช่างที่ทำ ที่ซ่อม ผู้แจ้ง และหมายเหตุ (บันทึกเป็น transaction เดียว)
- **ลบใบงาน** — ปุ่ม "ลบ" พร้อม pop-up ยืนยันที่บอกว่าจะลบอะไหล่กี่รายการและรูปกี่รูปไปด้วย
- คำนวณมูลค่าอะไหล่และค่าแรง / ส่วนลด / รวมทั้งสิ้น อัตโนมัติ (ไม่คิด VAT)
- แดชบอร์ด KPI, กราฟค่าซ่อมรายเดือน, รถที่ซ่อมบ่อย
- เพิ่มทะเบียนรถและสถานที่ซ่อมใหม่ได้
- **แนบรูปก่อน/หลังซ่อมได้จริง** — คลิกหรือลากรูปมาวางในหน้ารายละเอียดใบงาน
  ไฟล์อัปโหลดขึ้นเซิร์ฟเวอร์ทันที ลบได้ และจำนวนรูปในรายการงานอัปเดตตาม
  รูปที่แนบในฟอร์ม "แจ้งซ่อมใหม่" จะถูกอัปโหลดให้หลังใบงานถูกสร้าง
- **คลิกรูปเพื่อดูเต็มจอ** — เลื่อนดูรูปอื่นในใบงานเดียวกันด้วยปุ่มลูกศรบนจอหรือปุ่ม ← →
  ปิดด้วย Esc หรือคลิกพื้นหลัง · เปลี่ยนรูปจากปุ่มดินสอมุมขวาของช่อง ลบจากปุ่มกากบาท
- ช่องรูปในหน้า "เพิ่มทะเบียนรถ" ยังเป็นตัวอย่างในเครื่องเท่านั้น (ยังไม่บันทึกขึ้นเซิร์ฟเวอร์)

> รูปทั้งหมดเก็บใน Supabase Storage (bucket `job-photos`) ไม่ว่าจะอัปผ่าน Go API หรือจากหน้าเว็บบน Pages
> จึงเห็นรูปชุดเดียวกันทั้งสองทาง — ต้องตั้ง `SUPABASE_URL` + `SUPABASE_PUBLISHABLE_KEY` ใน `stores/.env` ด้วย

## ต่างจากไฟล์ standalone เดิมอย่างไร

- ฟอร์ม "แจ้งซ่อมใหม่" ของเดิมเป็นแค่หน้าตา กดบันทึกแล้วปิดเฉย ๆ — เวอร์ชันนี้บันทึกจริง
  ใบงานใหม่จะเข้ารายการทันทีด้วยสถานะ "แจ้งใหม่" และเลขที่ต่อจากเดิม (JR26-0155 ...)
- `<image-slot>` ของเดิมถูกแทนด้วยคอมโพเนนต์ `ImageSlot` ที่อ่านไฟล์เป็น data URL
- ข้อมูลทั้งหมดอยู่ในฐานข้อมูล (ไม่ใช่ state ในหน้าเว็บ) — การแก้ทุกอย่างบันทึกจริงผ่าน Go API
- ยอดเงินฝั่งฐานข้อมูลคำนวณด้วย generated column + view `job_totals` ตรงกับที่ `utils.js` คำนวณฝั่งหน้าเว็บ
- ปุ่มลบสถานที่ซ่อมเปลี่ยนเป็น "เลิกใช้งาน" (`is_active = false`) เพื่อไม่ให้ประวัติใบงานเก่าเสียอ้างอิง
- ไอคอนเดิมที่เป็นตัวอักษรสัญลักษณ์ (◧ ☰ ⬢ ＋ ⌂ ⌕ ▤ ×) ถูกออกแบบใหม่เป็น SVG ทั้งชุดใน `Icon.jsx`
